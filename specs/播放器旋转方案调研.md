# 播放器横竖屏旋转方案调研 — ZFPlayer / SJVideoPlayer(SJRotation) / KSPlayer

> 2026-11-13 · 服务于包 A 后的旋转收尾与包 B 排期。方法：拉取三家源码精读（引用均为 GitHub blob 链接，本文只写源码里可验证的行为，不写猜测）。
> 结论先行：三家分属三条路线；我们的「纯 transform、系统永不旋转」路线与 SJ/ZF iOS16 的「专用旋转窗口」**几何技巧完全一致**，差异在窗口与状态栏层；真正值得借的是三件小事（全屏态隐藏状态栏/Home indicator、退出瞬间闪帧兜底、动画时长对齐），路线本身不换。

## 一、三条技术路线总览

| 路线 | 代表 | 机制 | 状态栏/安全区 | 代价 |
|---|---|---|---|---|
| ① 系统旋转 | KSPlayer、AVPlayerViewController | present 全屏 VC + 改全局方向支持，交给 UIKit 真转 | 系统原生，状态栏/安全区全部真实 | 需 App 声明支持横屏；系统旋转动画与生命周期回调多；**我们此前「窗口反复翻转/振荡」的实证问题属于这一族** |
| ② 专用旋转窗口（混合） | **SJVideoPlayer iOS16+**、**ZFPlayer iOS16+** | 搬运 target 视图 + 一个专用 UIWindow 成为 key window（其方向掩码含横屏）→ **系统真的把界面转到横屏**，同时 target 上跑一段 0.3s transform 动画做视觉桥接 | 全屏态状态栏/安全区真实（窗口真转了） | 需 AppDelegate 实现 `supportedInterfaceOrientationsForWindow:` 按窗口转发；旋转期间 App 其余界面被盖住；实现复杂度最高 |
| ③ 纯 transform | 抖音式信息流播放器、**我们（包 A）** | App 锁竖屏永不转，播放视图（或 layer）搬进屏幕级容器，transform ±90° + 放大铺满 | 状态栏保持竖屏样式、安全区需自行映射 | 状态栏/Home indicator 不随画面转（需手动隐藏或接受）；安全区手动算 |

**我们的定位**：路线 ③。这是有意的产品/工程决策——AGENTS 12 已记「锁竖屏、系统窗口方向永不翻转」，此前系统旋转路线导致过布局振荡、跳变、每 pass 全量重排（相关补丁已全部退役）。本文所有「借鉴」都在路线 ③ 内部做，不换路线。

## 二、SJVideoPlayer（SJRotation）源码解析

文件（repo `changsanjiang/SJVideoPlayer`，源码在 SJBaseVideoPlayer pod 内）：

- [SJRotationManager.m](https://github.com/changsanjiang/SJVideoPlayer/blob/master/Example/Pods/SJBaseVideoPlayer/SJBaseVideoPlayer/Common/Implements/SJRotationManager.m) — 抽象基类 + 窗口准备 + 设备方向观察
- [SJRotationManager_iOS_16_Later.m](https://github.com/changsanjiang/SJVideoPlayer/blob/master/Example/Pods/SJBaseVideoPlayer/SJBaseVideoPlayer/Common/Implements/SJRotationManager_iOS_16_Later.m) — iOS16+ 主实现
- [SJRotationManager_iOS_9_15.m](https://github.com/changsanjiang/SJVideoPlayer/blob/master/Example/Pods/SJBaseVideoPlayer/SJBaseVideoPlayer/Common/Implements/SJRotationManager_iOS_9_15.m) — 旧系统（KVC 强设方向 + shouldAutorotate 协同）
- [SJRotationFullscreenWindow.m](https://github.com/changsanjiang/SJVideoPlayer/blob/master/Example/Pods/SJBaseVideoPlayer/SJBaseVideoPlayer/Common/Implements/SJRotationFullscreenWindow.m) / [SJRotationFullscreenViewController.m](https://github.com/changsanjiang/SJVideoPlayer/blob/master/Example/Pods/SJBaseVideoPlayer/SJBaseVideoPlayer/Common/Implements/SJRotationFullscreenViewController.m) — 专用窗口与承载 VC
- API 定义：`SJRotationManagerDefines.h`（`target` = 要搬的播放器容器视图、`superview` = 原父视图）

### 机制要点

1. **专用旋转 UIWindow（`SJRotationFullscreenWindow`）**：`windowLevel = StatusBar-1`，root VC（`SJRotationFullscreenViewController`）声明 `supportedInterfaceOrientations = AllButUpsideDown`。初始化时做一段「预热舞蹈」：两层 0 秒动画里把窗口以 Normal-1 级别显示再隐藏、换到 StatusBar-1 再隐藏——目的是提前让 UIKit 建立该窗口的方向上下文，首次旋转不卡顿。
2. **方向源 = `UIDeviceOrientationDidChangeNotification`**，只认 Portrait / LandscapeLeft / LandscapeRight（FaceUp/FaceDown/Unknown 直接忽略）。
3. **旋转门控 `allowsRotation`（七条闸门）**：窗口准备中→禁；App 非 active→禁（`SJRotationActivation` 监听 willResignActive/didBecomeActive）；「旋转中但未转场」→放行（允许打断重定向）；当前==设备方向→禁；手动强制（`forcedRotation`）绕过禁自动开关；方向不在支持掩码→禁；「旋转中且转场中」→禁；外部 `shouldTriggerRotation` block 拒绝→禁。两级状态 `rotating` / `transitioning` 把「打断」与「动画互斥」分开。
4. **iOS16 进全屏流程**（Portrait→Landscape，逐行核对）：
   1. `currentOrientation = 目标方向`（这会改专用窗口的方向掩码）；
   2. 把 `target`（播放器容器**整个视图**）从原父视图搬到主窗口，`frame` = 原位置的窗口坐标（**视觉零跳变起点**）；
   3. 旋转窗口 `makeKeyAndVisible` + 对 keyWindow/rootVC 与旋转窗口/rootVC 各调一次 `setNeedsUpdateOfSupportedInterfaceOrientations`；
   4. 0.3s 动画：`bounds → {屏高, 屏宽}`、`center → 竖屏屏幕中心`、`transform → ±π/2`——**与我们包 A 完全相同的几何技巧**（横屏尺寸的视图转 ±90° 后足迹恰好铺满竖屏屏幕）；
   5. 动画完成：`transform = identity`、`bounds = 窗口 bounds`，target 重新挂进旋转窗口的 VC 视图——此后由窗口自身（已被系统转到横屏）承载，不再依赖 transform；
   6. 再补一次 `setNeedsUpdateOfSupportedInterfaceOrientations`。
5. **退全屏**：target 带着横屏 bounds+transform 搬回主窗口 → `[SJRotationPortraitOrientationFixingWindow makeKeyAndVisible]`（一个只允许 Portrait 的透明单例窗口，把**场景钉回竖屏**）→ 隐藏旋转窗口 → 0.3s 反向动画缩回原卡位 → 完成后归位原父视图。中途 `snapshotViewAfterScreenUpdates:YES` 强制渲染一帧防闪。
6. **状态栏**：旋转进行中由 manager 强制「按目标方向隐藏」（`prefersStatusBarHiddenForRotationFullscreenViewController`），稳定后交给 actionForwarder；iOS16 实现里稳定全屏是**显示**状态栏的。
7. **Home indicator**：全屏 VC `prefersHomeIndicatorAutoHidden = YES`。
8. **安全区坑（与我们同款问题）**：`SJRotationFullscreenView.safeAreaInsets` 覆写——视图还是竖屏尺寸时借用 keyWindow 的 insets，横屏尺寸后用系统真值。iOS<16 另有 `_setContentOverlayInsets:andLeftMargin:rightMargin:` 私有方法 swizzle（已被两库同款复制，iOS16+ 弃用）。
9. **宿主契约**：类方法 `+supportedInterfaceOrientationsForWindow:` 供 AppDelegate 的 `application:supportedInterfaceOrientationsForWindow:` 转发（专用窗口→当前方向，其余窗口→Portrait）。**不转发则每窗口掩码不生效**。

### 对 de08f27 的印证

`SJOrientation` 直接取 `UIDeviceOrientation` 枚举值；iOS16 实现里 Portrait→LandscapeLeft = `+M_PI_2`、Portrait→LandscapeRight = `-M_PI_2`。我们 `PlayerOrientationTrigger` 的重力角映射（顶朝右/CW → -π/2）与其一致（详见 §四）。

## 三、ZFPlayer（ZFLandscapeRotationManager）源码解析

文件（repo `renzifeng/ZFPlayer`）：

- [ZFLandscapeRotationManager_iOS16.m](https://github.com/renzifeng/ZFPlayer/blob/master/ZFPlayer/Classes/Core/ZFLandscapeRotationManager_iOS16.m) — **与 SJ iOS16 实现几乎逐行同构**（搬家→makeKey→setNeedsUpdate→0.3s bounds/center/transform→re-parent），不再展开
- [ZFLandscapeRotationManager_iOS15.m](https://github.com/renzifeng/ZFPlayer/blob/master/ZFPlayer/Classes/Core/ZFLandscapeRotationManager_iOS15.m) — 旧系统路线：**私有 API `[UIDevice setOrientation:]`（NSInvocation）** + `attemptRotationToDeviceOrientation` 触发 shouldAutorotate，动画在 `viewWillTransitionToSize` 回调里协同 0.3s
- [ZFLandscapeWindow.m](https://github.com/renzifeng/ZFPlayer/blob/master/ZFPlayer/Classes/Core/ZFLandscapeWindow.m) — 专用窗口，`windowLevel = StatusBar-1`，`pointInside` 恒 YES
- [ZFOrientationObserver.m](https://github.com/renzifeng/ZFPlayer/blob/master/ZFPlayer/Classes/Core/ZFOrientationObserver.m) — 每个 player 一份观察者（关联对象），方向源同为 `UIDeviceOrientationDidChangeNotification`
- [ZFPlayerController.m](https://github.com/renzifeng/ZFPlayer/blob/master/ZFPlayer/Classes/Core/ZFPlayerController.m) — 入口层
- [UIViewController+ZFPlayerRotation.m](https://github.com/renzifeng/ZFPlayer/blob/master/ZFPlayer/Classes/Core/UIViewController+ZFPlayerRotation.m) — Tab/Nav 旋转转发 categories + iOS13–15 安全区 swizzle

### 机制要点

1. **fullScreenMode 三态**（ZFFullScreenMode）：`Automatic`（按设备当前方向自动选横/竖）、`Landscape`（转横进全屏）、`Portrait`（**竖屏拉满**，不旋转——`ZFPortraitFullScreenMode` 还分 ScaleToFill / AspectFit）。竖屏拉满态由 `ZFPortraitViewController` 承载。
2. **cell 场景一等公民**：`ZFRotateType = Normal / Cell`，`updateRotateView:containerView:` 同时登记小窗容器——与我们的 feed 场景同构。
3. **动画时长默认 0.30s**（`duration` 可配）；`orientationWillChange/orientationDidChanged` 两个回调给 UI 层重建布局。
4. **锁定/禁转**：`lockedScreen`（锁屏按钮语义）、`allowOrientationRotation`（自动旋转开关）、`ZFDisablePortraitGestureTypes`（竖屏态禁用哪些手势）。
5. **状态栏三件套**：`fullScreenStatusBarHidden / fullScreenStatusBarStyle / fullScreenStatusBarAnimation`。
6. **息屏抑制**：全屏 VC `UIApplication.shared.isIdleTimerDisabled = true`（KSPlayer 同款，见 §五对照表）。
7. iOS16 退出流程：contentView 带横屏 bounds+transform 搬回主窗口 → `makeKeyAndVisible` 主窗口 → 隐藏旋转窗口 → 0.3s 缩回原卡位 → 归位。与 SJ 的差别仅在 SJ 多一个「竖屏钉住」辅助窗口防窗口切换瞬间的方向闪变。
8. **iOS15 私有 API `setOrientation:` 有审核风险**，仅适用于 iOS<16（我们已经只支持 iOS 26 工程，无意义，记录备查）。

## 四、±π/2 方向映射的枚举语义坑（de08f27 的独立印证）

**`UIDeviceOrientation` 与 `UIInterfaceOrientation` 的 Left/Right 语义是互换的**（`UIInterfaceOrientationLandscapeLeft == UIDeviceOrientationLandscapeRight`）。两库的源码写法看似矛盾，实则一致：

| 库 | 枚举语义 | 源码写法 | 换算成设备语义（顶朝左/CCW、顶朝右/CW） |
|---|---|---|---|
| SJ | `SJOrientation = UIDeviceOrientation` | Portrait→LandscapeLeft = **+π/2** | 顶朝左(CCW) → **+π/2** |
| ZF | `UIInterfaceOrientation` | InterfaceLandscapeLeft = **-π/2** | 顶朝左(CCW) → **+π/2**（interface Left == device Right） |
| 我们 | CoreMotion 重力角 | `rotationAngle(forGravityAngle:)`：+90°(顶朝右) → -π/2 | 顶朝左(CCW) → **+π/2** |

三家在设备语义下完全一致：**顶朝左 → +π/2，顶朝右 → -π/2**。de08f27 修的方向映射与两家开源实现互相印证，这条不需要再动。今后若有人对照别的库源码看到「符号相反」，先查枚举语义再怀疑实现。

我们的文件：`player/PlayerFullscreenController.swift`（容器+动画+手势）、`player/PlayerOrientationTrigger.swift`（CoreMotion 判稳）、`player/PlayerSurfaceContainer.swift`（单例 surface）、`DramaPlayerViewModel.fullscreenRotationAngle`。

| 关注点 | SJ / ZF | 我们 | 评价 |

| 出场动画 | 反向缩回原位 + snapshot 防闪帧 | 反向缩回 + layer 先回搬再移除容器 | 顺序正确（先 restore 再 removeFromSuperview）；若真机见闪帧，补 `CATransaction` disable actions 或 snapshot 兜底 |
| 方向源 | `UIDeviceOrientationDidChangeNotification` | CoreMotion 重力角连续倾角 | 我们锁竖屏后 UIDevice 通知失效（代码注释有实证），CoreMotion 是正确选择 |
| 判稳/防抖 | 无稳定窗，通知即转（靠门控兜底） | 55°/28° 滞后带 + 0.6s 稳定窗 + 平放跳过 | **我们更严**，45° 边界抖动已被滞后带覆盖 |

| App 生命周期 | `SJRotationActivation`（resignActive 禁转） | CoreMotion 后台自动暂停 + `teardown()` 即时还原 | 基本等价；回前台瞬间无特殊处理，暂未观察到问题 |

| 状态栏 | 全屏 VC 控制（SJ 旋转中隐藏；ZF 三件套可配） | **未处理**（状态栏保持竖屏样式叠在全屏画面上） | **缺口，见 §六 P1** |
| Home indicator | 全屏 VC `prefersHomeIndicatorAutoHidden = YES` | **未处理** | **缺口，见 §六 P1** |
| 息屏抑制 | 两库全屏时 `isIdleTimerDisabled = true` | 未显式设置（AVPlayer 对可见视频层默认抑制息屏） | 若真机发现会息屏再显式加；顺手加也无害 |
| 竖屏片源 | ZF `fullScreenMode=Portrait` 竖屏拉满（Fill/Fit） | `videoGravity`：竖屏片源 fill、未知按竖屏 | 已对齐（我们由片源方向驱动，更贴合剧集产品） |

## 六、可执行借鉴清单

**P1（建议尽快做，小改动）**

1. **全屏态隐藏状态栏 + Home indicator**：两家全屏都隐藏 Home indicator、SJ 旋转全程隐藏状态栏。我们全屏容器不在 VC 层级里，需从根上控制——根 VC（或其宿主）依「播放器是否全屏」的共享状态返回 `prefersStatusBarHidden` / `prefersHomeIndicatorAutoHidden`。改动点：一个全屏态广播（已有 `DramaPlayerViewModel.$isFullscreen` 可透传）+ App 根 VC 两行 override。（**仍未做**，2026-11-14 全库复查无 prefersStatusBarHidden / prefersHomeIndicatorAutoHidden 落点）
2. ~~**动画时长 0.35s → 0.30s**（可选）~~ **已完成**（11-13 全屏修复批次，代码现为 0.30s）。

**P2（真机回归后按需）**

3. **进/出瞬间闪帧兜底**：若 §7 ⑭ 复验发现 layer 搬家瞬间闪帧，参考两库加 `snapshotViewAfterScreenUpdates` 占位，或把 layer 回搬包进 `CATransaction.setDisableActions`。
4. **息屏抑制确认**：真机播 10 分钟不碰屏幕，若息屏则显式 `isIdleTimerDisabled`（随全屏/播放状态开关）。
5. **回前台瞬间的旋转门控**：若复验发现回前台时姿态误触发，参考 `SJRotationActivation` 加 didBecomeActive 后短暂静默窗。

**P3（明确不做，记录理由）**

- **专用旋转窗口路线（路线 ②）**：需要 AppDelegate 按窗口转发方向掩码、系统真实旋转场景——与「锁竖屏永不转」的拍板冲突，会重新引入系统旋转族问题；收益（真实状态栏方向）对信息流形态价值有限。
- **iOS15 私有 `setOrientation:`**：审核风险且我们目标系统 ≥iOS 26。
- **`requestGeometryUpdate` 编程旋转**：同路线①，需 App 声明支持横屏才能转，与锁竖屏冲突。
- **lockedScreen 锁定按钮**：产品无入口（拍板过）。

## 七、给包 B 的直接输入

1. **结构已同构**：SJ/ZF 的「全屏容器 + 控制层 + 手势三件套 + 订阅播放器状态」与我们的 `PlayerFullscreenController`（含全屏手势六条仲裁的全屏版）一一对应；包 B 把竖屏卡片 UIKit 化后，这套全屏代码无需重写，只需与卡片侧共享同一批 VM @Published（已在包 A 验证）。
2. **搬运粒度维持 videoLayer**：两库搬整视图是因为它们全屏时原位置本来就空（黑底）；我们的单例 surface 同时服务 feed 活跃卡与全屏，整视图搬走会让 feed 无画面——**包 B 不要改成搬 view**。
3. **ZFRotateTypeCell 的教训**：cell 场景必须同时登记「小窗容器 + 全屏容器」两个落点（`updateRotateView:containerView:`）——我们 `PlayerSurfaceContainer` 对位活跃卡的逻辑已经覆盖，包 B 拆分文件时别把这条链拆断。
4. **退出动画的落点必须实时取**：两库每次动画前都 `convertRect` 现算 target frame（不缓存），我们 `performExit` 里也是现算——保持，卡片切换后缓存会指向旧卡。
