依赖方向：**View → ViewModel → Service → 系统/Model**，单向不可反向；组装根只做 DI。

1. 上下滑资源调度唯一入口是 `PlaybackQueueService`；**后续本地推荐算法只改 `resolveNext(from:in:)` / `resolvePrevious(from:in:)`**，不动 View / 容器 / ViewModel。

2. 播放页用 **UIKit 原生分页**：`PlayerPagingScrollView`（`UIViewRepresentable` 包 `UIScrollView.isPagingEnabled = true` + `UIHostingController` 承载 SwiftUI 卡片）。纵向 pan 由 UIKit 独占，**卡片内禁止任何连续手势（包括局部 DragGesture）** —— 曾因进度带 390×120 的局部 DragGesture 吃掉全部纵向滑动，导致分页完全滑不动。手势分两类落位：
   - **连续手势**（水平 seekPan / 左缘 edgePan 返回）→ UIKit recognizer 挂在同一 UIScrollView 上，`cancelsTouchesInView = false`，通过 delegate 与系统 pan 同时识别；seekPan **全域起手**（.began 即翻转 `isSeekGestureActive` 仲裁闸门）；**横向 seek 已全屏化（2026-11-11 用户拍板）**：相对映射（拖动位移/屏宽 = 进度增量，一屏宽≈全片时长），落点无关、无命中带概念——勿加回带内过滤或绝对映射（带几何曾致清屏盲按整批静默被拒）；左缘 30pt 内起手不 seek（保留给 edgePan 返回）。**横滑起手必须独占本次触摸（panLock，2026-11-14 修「左右滑动上下晃动」）**：`Coordinator.lockSystemPan` 在 seekPan/edgePan .began 即 `panGestureRecognizer.isEnabled=false`（系统 pan 启动阈值低、人手横滑必有 y 微动，不锁则系统 pan 抢先 begin 锁纵向驱动 contentOffset——全程上下晃 + 松手 velocity.y>0.3 被 willEndDragging 误判翻页）+ `realignToCurrentPage` 归位已拖走的纵向位移；全部结束分支（ended/cancelled/failed）与 dismantle 兜底 `unlockSystemPan`（漏恢复 = 播放页永久滑不动），幂等标志 `systemPanLocked` 防双手势结束顺序互踩。纵向滑动不受影响：seekPan 被方向过滤拒绝（`shouldBegin` 用 `abs(t.x) > abs(t.y)` 严格大于——45° 及更陡交给系统 pan 切集；起手转水平不受影响，.began 的 panLock 会 cancel 系统 pan 抢占回来）。「先起者独占本次触摸」的仲裁哲学从 2x↔seek 延伸到 seek↔scroll。**坐标陷阱：`location(in:)` 给出的是内容坐标（含 contentOffset），喂几何换算前必须先转屏幕坐标**——曾因未换算除第一页外全失效。
   - **离散手势**（点按暂停 / 长按倍速）→ **卡片内 SwiftUI 手势**（`.onTapGesture` / `.onLongPressGesture(pressing:)`）。SwiftUI 手势按深度优先解析：卡片上的 Button（返回/静音/点赞/收藏）天然优先于卡片手势，点控件不会连带暂停，**不需要控件区判定表**（曾用 `PlayerGesturePolicy.isTapOnControl` 几何表排除控件区，因每个新控件都要登记、维护成本高，已删）。
   - **长按 2x ↔ 水平 seek 冲突仲裁 = 「先起者独占本次触摸」**（真机日志实证后定的规则，改手势前勿破坏本条与相邻子条的约束）：拖动先起 → seek 独占（**seekPan .began 起手即置 `isSeekGestureActive`**——判定点勿放首个有效 .changed「水平主导+dx>6」：清屏下带外起点的横滑、斜起手转水平的快滑，都会让长按 0.15s 的 perform 插进空窗闪 2x，2026-11-11 修；卡片 perform 起手前查 `playback.isSeekGestureActive`，拖动中长按被识别也不得起 2x）；长按先起 → 2x 独占（`VM.seek` guard `isFastForwarding`，按住 2x 期间漂移不 seek；`maximumDistance` 放开到 10_000，**不靠位移距离掐 2x**——原 40pt 让按住 2x 的手一漂就掉回 1x）。短按 2x 快速松手会被同时认成长按+单击（误暂停），卡片用 250ms 抑制窗吞掉；seekPan **抬手不补 seek**（防「松手清 2x 后 .ended 的 seek 穿过闸门」的竞态跳变）。**seek 独占的触摸抬手还要开同样的 250ms 吞单击窗**（VM `tapSuppressionDeadline`，2026-11-13 修）：seekPan `cancelsTouchesInView=false` 且纯横滑时系统分页 pan 不 begin，SwiftUI tap 全程存活，不设窗则每次横滑结束误 TAP→暂停，勿删窗。**2x 只能在 perform（按满 0.15s）里起，勿放 pressing(true)**——pressing 在触摸落下瞬间即回调（先于任何位移判定），放那里每次快速滑动（含翻页/清屏后的轻扫）都误触 2x（2026-11-11 修）。
   - 手势几何已无命中带（2026-11-11 全屏化，`PlayerGesturePolicy` 仅剩 scrub 灵敏度纯函数）；进度条 HUD 的视觉坐标仍在 `DramaPlayerView` 的 designFrame（20,744,350），移动进度条时同步 HUD 与相关注释即可，不再有手势几何与它耦合。边界提示由 ViewModel 给出，但触发点不是「停稳末页」——用户拍板 2026-11-14：**末页再往下滑一次（想看下一集但已无资源、翻不出去）才提示「已经到底了」**（`scrollViewWillEndDragging` 里翻页目标超出最后页时经 `onPullBeyondEnd` 回调 → `PlayerFeedViewModel.pulledBeyondEnd()`，一次会话一次；停稳末页本身是正常状态不提示，抖音同行为）。
   - 曾使用 SwiftUI `ScrollView + .scrollTargetBehavior(.paging) + .scrollPosition(id:)`，因与卡片内 `GeometryReader` / 子视图手势 / 尺寸计算冲突导致**完全滑不动**（多轮排障无效），已弃用，勿改回。

3. 播放器采用**单播放器常驻 + 滚动停稳防抖后切 item**（ZFPlayer / 开源抖音实践），禁止每次滑动新建 AVPlayer；暂不引入多 player pool。**播完自动连播（2026-11-14）只走「信号 + 既有停稳管线」，勿另立加载链路**：`DramaPlayerViewModel` 只发播完信号（`.AVPlayerItemDidPlayToEndTime`，object: nil + 回主线程判「事件对象 === currentItem」过滤迟到事件，`onPlaybackEnded` 闭包）→ `PlayerFeedViewModel.playbackDidEnd()` 按 hasNext/slots 算下一集置 `playback.autoAdvanceSort`（@Published）→ `PlayerPagingScrollView` Coordinator 订阅动画翻页（`scrollToSort`）并复位信号 → `scrollViewDidEndScrollingAnimation`→`report` 复用 scrollID→schedulePageSettle→pageSettled（预热池/autoplay 全在里面）；末集播完不跳（停在末帧），下一集未下载照常跳占位页。**片尾停留态不复活（2026-11-14 拍板）**：`togglePlayback` 对「暂停且位于片尾（now ≥ total-0.2）」直接 SKIP 不 seek(0) 重播——末集播完误点一下曾整集从头放；重看走横向 seek 拖离片尾后点按恢复。勿把「算下一集」或「直接 load 下一集」塞进播放 VM——它不持有队列/槽位知识。秒开链路由三件事共同保证，改切集加载行为时需一起评估：`PlaybackPlayerService` 的**相邻集资产预热池**（停稳播当前集时提前 `asset.load(.isPlayable)`（async 岛）完成相邻集 m3u8 拉取解析，`makeItem` 命中即 HIT；**wanted 名单必须含当前集+两侧邻居**——只报邻居会被自己的淘汰逻辑打穿，曾全 MISS；刚离开的集作为邻居重暖是回滑 HIT 保险，勿加「跳过正在播的集」过滤，曾因 playingSort 过滤致回滑必 MISS）+ `DramaPlayerViewModel` 的 **KVO 直挂就绪判定**（status 一变立刻翻转 isReady，4s 看门狗兜底，勿改回轮询）+ **spinner 800ms 延迟显示**（`isLoadingSlow`；阈值依真机实测定——HIT 就绪 642–871ms，300ms 每滑必闪）。

4. 全屏横向拖动 = 相对 scrub（拖动位移/屏宽换算进度，一屏宽≈全片时长），左缘 30pt 起手除外（保留给返回手势）；垂直滑动只切集，不碰进度。清屏下 seek 照常生效且全屏可用，进度条+时间瞬态淡入（`VM.isScrubbing`，松手停留 800ms 淡出；开启清屏闪现 1.5s 作空间参照）；**勿复用 `isSeekGestureActive` 驱动该 UI**——那是非渲染的手势仲裁闸门，两者语义不同（一个管仲裁、一个管显示）。

12. **播放页锁竖屏 + 播放器容器自转全屏**（2026-11-13 重构，对齐 ZFPlayer/SJVideoPlayer rotate 模式，取代早期的卡片横屏 overlay 路线）：Info.plist 仅 Portrait，**系统窗口方向永不翻转**——勿再往卡片/页面加「随系统旋转」类实现（曾致布局振荡、跳变、每 pass 全量重排，相关补丁已全部退役）。竖屏 feed 里横屏片源 letterbox（gravity 统一由 `PlayerPagingScrollView.videoGravity` 设置：横屏片源 fit、竖屏片源 fill，presentationSize 未知按竖屏 fill，**勿随持屏方向切换**——fit↔fill 二值跳变即「中间条突变全屏」的根因）。全屏 = `PlayerFullscreenController` 把可搬运视频子层（`PlayerSurfaceUIView.videoLayer`，view 背板层不能搬）搬进 keyWindow 容器，transform 旋转 ±90°（按重力角跟随设备实际转向，写死单侧会令另一半转向内容上下倒置，见 PlayerOrientationTrigger→VM→PlayerFullscreenController 链）+等比放大连续铺满（退出反向动画）；触发 = `PlayerOrientationTrigger` 姿态判稳（滞后阈值 55°/28° + 0.6s 稳定窗，仅横屏片源 + isReady，无按钮入口）；全屏控制层 `PlayerFullscreenControlsView`（左上返回 icon=退出全屏、点按呼出 3s 收起、Combine 订阅同一个 VM，状态不另立源）。视频由单例容器渲染（`PlayerSurfaceUIView` 压在视频上」。**横屏底栏左侧是播放/暂停，不是「下一集」**（2026-11-15 用户拍板）：`barPlayButton` 订阅 `playback.$isPlaying`，与中部 48×48 大按钮同源同拍翻面；「下一集」已移入顶栏「更多」菜单，勿把 ▶| 图标放回底栏（用户实机会把它当播放键点，且它不会翻面）。底栏保持两行：① 播放/暂停 · 当前时间 · 进度条 · 总时长 ② ♥ ★ 倍速 清晰度 选集（**清晰度按片源实际分辨率显示**，2026-11-15 修：`qualityButton` 原写死「1080P」，720P 片源也标成 1080P；现由 `DramaPlayerViewModel.videoQualityText` 订阅刷新，取值 `VideoQualityLabel.text(for:)` —— 按短边折算，1920×1080 → 1080P、1280×720 → 720P、3840×2160 → 4K，未知给「—」；读取点与 `refreshVideoOrientation` 同一处，presentationSize 有效才更新）。**播放/暂停图标必须是「一个视图按状态重绘」（`PlayPauseGlyphView(box:)`，中部 48 / 底栏 20），不能用两个视图来回 `isHidden`**——隐显过渡会留一帧「两个都在/两个都不在」，真机上就是「点一下 icon 闪一下」（2026-11-15 用户实报）。同理 `FullscreenGlyphView.glyphScale` 的 `didSet` 有「值未变不重绘」守卫：`layoutSubviews` 被 1Hz 进度 tick 反复触发，没守卫等于每秒强制重绘全部图标。**`isPlaying` `play()`、表现为「点不动」。**全屏横屏控制层的左右边距只有一个常量 `M.edge`**（`PlayerFullscreenControlsView.M.edge = 98`，画布单位，真机 = edge×sx，2026-11-15 用户拍板「设为一个常量后续不合适可以自己调节」）：返回 / 亮度 / 点赞 / 底栏播放键的左缘、更多 / 锁定音量 / 选集的右缘、以及进度行「播放键 → 时间 → 轨道 → 时长」整行两端，全部钉在 `X(edge)` 与 `X(844-edge)` 两条竖线上；零碎坐标别再写死，改间距只改这一个数（`moreInkInset` 是「⋮」的墨迹补偿——三枚圆点只有 2.8 宽、居中在 16 宽盒里，盒子要右移 6.6 墨迹才与边距线齐平；锁定/音量的 44 方钮底整盒填充，不需要补）。**进度行右端不能按「轨道右缘 = 19. **选集面板（竖屏弹层 + 全屏抽屉）的集号与状态必须与剧集页选集区一致**（2026-11-15 用户实报「统一按照一二三四的方式排布不正确」）：
   - **集号唯一来源是队列槽位的 `sort`**（`PlaybackQueueService.slots`），**不要再写 `1...total` 按下标编号**：用户可能只下了第 10~12 集、或挑了第 3、7 集，按下标编号会让面板显示出一批不存在的集。
   - **槽位集号 = `known ∪ 缓存 ∪ 磁盘`，再按「本剧总集数」把 1…N 补齐**（2026-11-15 二次修，用户实报「11 集只下了 7-11，面板只显示 7-11，没 1-6」）：只取并集时，三个来源都不含 1~6 就一格都没有。总集数唯一可信来源是剧集元数据 —— `DramaCache.episodeTotal(forSeriesName:)`（详情接口 `episode_count` 与已缓存最大集号取大者；**下载页入口只有剧名 + 磁盘，这是唯一能离线得知「一共多少集」的字段**），再与 `known.max() / 缓存.max() / 磁盘.max()` 取大者作为上界，`1…上界` 里没有槽位的集号全部补成「未下载」。补出来但站点其实没有的集点按会走「站点未开放/缺元数据」提示，比从面板上消失好。`PlaybackQueueService.totalEpisodeCount` 就是这个上界，**「选集 · 全 N 集」与全屏「下一集」边界用它，不要用 `slots.count`**（跳号时会少数）。
   - **按剧名反查必须容错**（`DramaCache.resolveDramaID`）：下载页入口拿到的是**剧目录名**（已被 `DownloadEngine.sanitizeTitle` 去掉 `（）/:` 等字符），而 `drama_cache.name` 存接口原名，精确匹配会整条落空（面板于是只剩磁盘那几集、全部显示「待下载」）。规则 = 先精确匹配，未命中再按同一套安全化规则比对一次，同名多剧取最近抓取。
   - 每格状态由 **`player/EpisodePanelService`** 装配成 `EpisodePanelItem`（Model 在 `PlaybackModels.swift`）：`phase` = 磁盘账本 `slot.isAvailable` 优先，其次 `DownloadTask` 按「`seriesName` + `第%02d集`」匹配的 state/current/total（与 `DramaPageViewModel.downloadPhase` 同一口径）；`playable` 取 `DramaCache` 的 `drama_episodes.playable`（缓存缺失默认 `true`，点击走「缺元数据」提示，不假灰）。
   - **点按统一收口到 `PlayerFeedViewModel.selectEpisode(sort:) -> Bool`**：先 `refreshAvailability()` 对账磁盘；已下载 → `playback.autoAdvanceSort = sort`（走既有翻页/停稳管线）返回 `true`；未下载 → `EpisodePanelService.requestDownload` 入队（复用 `SeriesDownloadCoordinator` + `DramaSession`）返回 `false`。**返回 true = 面板收起**（真的切了集，或点的就是当前集——同集点按必须给反应，否则用户会反复点）；返回 false 时**留下面板**（看进度环与标题提示）；正在下载再点只提示、不取消（取消下载归剧集页，别在播放页加这条）。
   - **全屏抽屉走 `DramaPlayerViewModel.episodePanelSubject`（`CurrentValueSubject<EpisodePanelState>`）这个专用通道，不要挂 `objectWillChange`**：后者会让每次进度 tick / 播放态翻转都重绘整块抽屉。`onEpisodeSelected` 闭包同样由外部注入（播放 VM 不持有队列/下载知识）。抽屉 `apply(state:current:)` **只在集号列表变化时重建网格**，只是下载态/提示变化就地重配每格——否则每 0.3s 的进度更新都会重建格子、把滚动位置拽回当前集并闪一下。
   - 视觉（墨本轨，与剧集页语义对应）：当前集 = 朱砂数字 + 4pt 点 + 朱砂描边底；已下载 = 墨白数字；未下载且可播 = 数字压暗（`overlayInkSub`）+ 右下角 7×8 下箭头（`EpisodeTodoGlyph` / `EpisodeTodoGlyphView`，对应剧集页 `.dl-todo`）；站点未开放 = 更淡且无箭头；排队 = 淡环、下载中 = 朱砂弧（可带 `strokeEnd` 进度）、失败 = 朱砂整环。**箭头落位顺序：先 `.frame(7×8)` + `.padding(4)` 再 `.frame(边,边,alignment:.bottomTrailing)`**——反过来会把整块放大 8pt 溢出格子、箭头被裁在边缘外（模拟器实测踩到）。
   - 一次性提示（已加入下载队列 / 正在下载 / 站点未开放 / 缺元数据）显示在**面板标题位**（`选集` 处，12pt 朱砂，2.4s 后恢复），竖屏与抽屉共用同一口径；不要另加 toast 层（全屏容器里没有 toast 通道）。
   - 验收：模拟器无法点按，只能造目录态 + 定帧截图 —— 例如把样张目录改成「第 01/02/10/11/12 集存在、第 03 集缺失」，面板应显示 `1 2 3 10 11 12`（3 带下箭头），抽屉与竖屏弹层一致；再验「共 11 集只放第 07~11 集」必须显示 `1…11`（1~6 压暗带下箭头）、胶囊写「全 11 集」。Debug 定帧开关：`-playerPreview -playerSeries <剧名> -playerNoKnown -playerStart 7 -playerPanel episode`（`-playerNoKnown` = 模拟下载页入口，请求里不带 knownSorts）。

23. **选集格「选中 + 下载」叠加时，边缘环整套换纸白**（2026-11-15 用户拍板「下载边缘进度颜色应该是白色的」）：
