# 图标坐标口径约定（SmartDownloader · 纸墨双轨）

> 起因：同一枚「设置」齿轮出现了 **22 空间** 与 **24 视口** 两份等价路径，容易被误当成同一份资产反复替换。本文档固定两套口径的**使用边界**。

## 结论先说

| 口径 | 用在哪 | 节点/尺寸 | 描边 | 落地效果 |
|---|---|---|---|---|
| **A · 22 空间**（画布图层口径） | Ardot 画布上的 tab 图标层 | 22×22 节点，图形墨面 Ø18–18.6 | `strokeWidth = 1.3`（节点本地单位） | 与浏览/下载同族同口径，三枚墨核齐平 18×18px |
| **B · 24 视口**（代码交付资产口径） | 给代码端替换 SF Symbol 用的独立 `.svg` 文件 | 24 viewBox，节点 17×17，图形墨面 Ø17.0 | `stroke-width = 1.8`（24 视口单位）→ 渲染 1.275px | 仅作资产，**不进画布图层** |

**两套不要混。** 把 B 口径的文件贴进画布 22 容器，渲出的齿轮会比两个圆环小一圈（Ø17.0 vs 环的墨核 18×18）。

## 为什么 Ardot 是节点本地 1:1（没有 24 内置网格）

实测（导出 SVG 原文）：

- `19:94` 夜间月亮，节点 13.3463×13.3463 → 导出 `width="14.6463" height="14.6463"`，即 **节点尺寸 + 描边 1.3 外扩**；路径坐标是节点本地值。
- `22:158` 齿轮，节点 22×22 → 导出 `width="22" height="22"`；路径 `transform="matrix(1 0 0 1 2.29985 2.29985)"`，墨面 Ø18.05。
- `22:148` 浏览，导出里圆环是 `r="9"` + `stroke-width="1.3"`，节点 22×22。

即：**导出画布 = 节点尺寸（+描边外扩），路径 1:1 落在节点本地坐标系**。所以在画布上直接以节点尺寸 + `strokeWidth` 控制光学尺寸即可，不必换算到 24 网格。

## 圆角：两条渲染管线，别混

- **独立 SVG 资产（口径 B，或我留的 `gear-settings-tab.svg`）**：靠 `stroke-linejoin="round"` + `stroke-linecap="round"`。**不要自己把圆角烘进路径** —— 贝塞尔曲率半径小于描边半宽时，齿顶会渲出白色破形小孔（visual-designer 已踩过并验证）。
- **Ardot 画布节点**：导出时 Ardot 会把描边转成填充路径（导出里是 `fill` + `transform`，没有 `stroke-width` 属性），圆角由 Ardot 自己的转换生成，不受上面那条约束 —— 所以画布节点里的齿轮没有出白孔。

## 齐平校验方法（改图标后跑一次）

在 1× 截图上量三枚 tab 图标的**墨核外接**（灰度 ≤170）：

```
浏览 18×18 (52 墨点) | 下载 18×18 (66 墨点) | 设置 18×18 (152 墨点)
```

- **外接尺寸**必须三枚相等（当前 18×18 ✓）—— 这是「齐平」的判据。
- **墨点数量**不要求相等：齿轮天然比圆环重（2–3 倍）。若要压平，齿轮描边降到 1.15–1.2（实测齿廓仍清晰：1× 最窄白通道 2px、中位 3px）。

## 落代码仍然用 SF Symbol

画布上的自绘图标只是**占位稿**。真机一律 `Image(systemName:)`，tab 三枚分别是 `safari.fill` / `arrow.down.circle` / `gearshape`，渲染点在 `Shared/MainTab.swift`（tab 条目与图标唯一定义点，`App.swift` 只消费）。自绘路径**不交付**，避免与系统图标风格脱节。

## 已知导出缺陷

`19:94` 夜间月亮：路径坐标到 `x = -1.2258`，而导出画布只有 节点 13.3463 + 描边 1.3 = 14.6463 → **左缘被裁约 0.58px**（4× 渲染实测最左墨列 = 第 0 列且有 13 个墨点，属硬裁）。修法：重落该路径让坐标全为正，或导出时给 0.6px 余量。
