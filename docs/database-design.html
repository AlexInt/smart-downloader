一个 SQLite 文件、四张表：剧集元数据 + 集清单 + 集级行为数据（含播放进度）

01总览与 ER 关系图

四张表住在同一个文件里。drama_cache 与 drama_episodes 由 DramaCache 维护（站点元数据镜像）； episode_actions 与 local_actions 由 EpisodeActionsStore 维护（用户行为数据）。 两组表没有外键约束，关联靠「同一套主键字段 + 代码约定」，删除时的联动由代码显式执行。

  • <散装条目>/playlist.m3u8
  • <普通文件>.mp4
为什么是「id 主表 + 路径兜底表」两张行为表： 剧集页入口带着 (site, drama_id)，能精确定位到服务端 episode_id， 于是点赞 / 收藏 / 播放位置都能挂在稳定的 id 上（重新下载、改目录、改名都不丢历史）， 并且可以和 drama_episodes JOIN 出「看到第几集」「哪些集收藏过」。 但散装 HLS、普通 mp4、以及从没进过剧集页缓存的历史条目根本没有服务端 id， 硬造一个 id 会把数据挂到别的集上，所以它们走 local_actions，以资源路径为主键。
维度现状
库文件位置Documents/drama_cache.sqlite3（Finder 文件共享可见可拷出）；设了环境变量 SMARTDOWNLOADER_DIR 时改写到该目录下（冒烟隔离用）
打开方式sqlite3_open_v2(path, READWRITE | CREATE)，每次调用开一次、用完 sqlite3_close
事务无显式事务：每条写语句各自 autocommit（一次 upsert 一条）
索引只有主键自带的索引，没有额外 CREATE INDEX；按 name 反查剧是全表扫（剧数量级小）
日志模式默认（未开 WAL）；未设 busy_timeout
外键未声明 FOREIGN KEY，未开 PRAGMA foreign_keys；一致性由代码保证
时间字段一律 ISO8601DateFormatter().string(from: Date()) 的 TEXT，非 Unix 时间戳
布尔字段SQLite 无 BOOLEAN，用 INTEGER 0/1
错误处理失败打印 CACHE FAIL[...] + sqlite3_errmsg，不静默；读失败返回 nil / 空集

02表 1 · drama_cache（一部剧一行）

站点剧集页的元数据镜像。维护方 Drama/DramaCache.swift；主键 (site, drama_id)。

字段类型约束 / 默认含义与取值写入方读取方
siteTEXT PK 1 NOT NULL 站点 origin，形如 https://host[:port]，由 DramaTarget.parse 从剧集页 URL 解析 saveInfo / savePageMetaload / seriesIdentity
drama_idTEXT PK 2 NOT NULL 站点侧剧 id（URL 路径 /drama/detail/<id>/ 里的数字，按文本存） saveInfo / savePageMetaload / seriesIdentity
nameTEXT可空 剧名。也是「下载页只有剧名」时反查身份的依据（WHERE name=?） saveInfoload / allSorts / seriesIdentity
update_statusTEXT可空 更新状态文案（如「已完结」「更新至第 N 集」），接口原样落库 saveInfoload → DramaInfo.updateStatus
coverTEXT可空 封面图 URL。优先 og:image，其次 twitter:image；空串表示没抓到 savePageMetaload → Entry.cover（详情页封面）
introTEXT可空 简介。meta[name=description] 或 og:description；播放页字幕区也用它 savePageMetaload → 详情页 / 播放请求 intro
tagsTEXT 可空 ALTER 追加 话题标签，空格分隔（如「#都市 #甜宠」）。来源见 page_meta.tags_source；空串视为「无」，否则会永久跳过补采 savePageMetaload → Entry.tags（播放页标签）
page_metaTEXT可空 DOM 收割结果的 JSON 字符串（合并式覆盖，字段清单见下一节） savePageMetaload → tagsSource 判定是否需补采
fetched_atTEXT可空 ISO8601 时间串。每次 saveInfo / savePageMeta 都刷新；同名多剧反查时按它倒序取最近一条 saveInfo / savePageMetaseriesIdentity(forSeriesName:)
建表语句（DramaCache.openDB，每进程首次打开时执行 CREATE TABLE IF NOT EXISTS）：
CREATE TABLE IF NOT EXISTS drama_cache (
    site TEXT NOT NULL,
    drama_id TEXT NOT NULL,
    name TEXT, update_status TEXT, cover TEXT, intro TEXT,
    page_meta TEXT, fetched_at TEXT,
    PRIMARY KEY (site, drama_id)
);
-- tags 列为后续追加（旧式做法：列已存在时 ALTER 报错被忽略，不参与 user_version）
ALTER TABLE drama_cache ADD COLUMN tags TEXT;

03表 2 · drama_episodes（一集一行）

接口返回的集清单镜像 + 下载状态。「是否已下载」的账本是磁盘（playlist.m3u8 存在即已下载）， 本表是它的镜像：下载完成立即 markDownloaded，选集面板每次打开 reconcileDownloaded 对账。

字段类型约束 / 默认含义与取值写入方读取方
siteTEXT PK 1 NOT NULL 同 drama_cache.sitesaveInfo / markDownloadedload / allSorts / seriesIdentity
drama_idTEXT PK 2 NOT NULL 同 drama_cache.drama_idsaveInfo / markDownloaded同上
episode_idINTEGER PK 3 NOT NULL 服务端集 id（不是「第几集」）。接口稳定标识，刷新集列表时按它 upsert；也是行为数据表的主键之一 saveInfo / markDownloadedload → ApiDramaEpisode.id / seriesIdentity
sortINTEGER可空 集号（第几集）。与磁盘目录名「第NN集」对应，播放页上下滑按它排序；markDownloaded 补建行时可能为 NULL saveInfoload / allSorts / seriesIdentity（集号→id 映射）
playableINTEGER可空 接口标记该集是否可播（0/1）saveInfoload → ApiDramaEpisode.playable
downloadedINTEGER DEFAULT 0 可空 是否已下载（0/1）。磁盘对账结果；删除单集 / 删全剧后由 reconcileDownloaded 置 0 markDownloaded / reconcileDownloadedload → ApiDramaEpisode.downloaded（选集格子打勾）
folderTEXT可空 落盘目录名（如 第01集），位于 Documents/Downloads/<剧名>/ 下；未下载为 NULL markDownloaded / reconcileDownloadedload → ApiDramaEpisode.folder
updated_atTEXT可空 ISO8601，本行最近一次写入时间saveInfo / markDownloaded / reconcileDownloaded（暂未用于业务判断） 
CREATE TABLE IF NOT EXISTS drama_episodes (
    site TEXT NOT NULL,
    drama_id TEXT NOT NULL,
    episode_id INTEGER NOT NULL,
    sort INTEGER, playable INTEGER,
    downloaded INTEGER DEFAULT 0,
    folder TEXT, updated_at TEXT,
    PRIMARY KEY (site, drama_id, episode_id)
);
实现与注释不一致（读代码时别被注释误导）： saveInfo 的注释写「既有集的 downloaded/folder 保留不动」，但实现是 DELETE FROM drama_episodes WHERE site=? AND drama_id=? 之后再逐集 INSERT … downloaded=0, folder=NULL —— 先删后插使 ON CONFLICT 永不触发， 刷新集列表会把下载标记清成 0/NULL，随后靠 reconcileDownloaded 的磁盘对账恢复。 行为数据表 episode_actions 是独立表，不受这次 DELETE 影响（点赞/收藏/进度不会被刷新冲掉）。

04表 3 · episode_actions（集级行为数据 · 主表）

维护方 Drama/EpisodeActionsStore.swift。一集一行、列即行为： 点赞、收藏、上次播放位置，以及后续要加的行为字段都加在这张表上。 主键与 drama_episodes 完全同构，所以能直接 JOIN 做关系查询。 行是「按需出现」的：只有真的点赞 / 收藏 / 播过，才会有这一行。

字段类型约束 / 默认含义与取值写入时机读取方
siteTEXT PK 1 NOT NULL 站点 origin，与 drama_cache / drama_episodes 同值 点赞 / 收藏：用户点按即时 upsert（setLiked / setSaved）

播放位置：只在关键时机 upsert（savePosition）—— 暂停、拖完 seek、切集、退出播放页、App 进后台；播放过程中只攒内存不写库

删除资源：removeActions 整行 DELETE 		播放页续播与状态回填（actions(for:)）

已下载列表 / 剧详情页副行（episodeActions(site:dramaID:) 按剧一次读全）

后续可做：看到第几集、收藏清单、未播完清单（JOIN 查询）
drama_idTEXT PK 2 NOT NULL 站点侧剧 id
episode_idINTEGER PK 3 NOT NULL 服务端集 id。由 MediaIdentity.episode 带入；重新下载 / 改目录 / 改名都不影响它
likedINTEGER NOT NULL DEFAULT 0 点赞（0/1）。播放页右侧点赞按钮的状态
savedINTEGER NOT NULL DEFAULT 0 收藏（0/1）。播放页右侧收藏按钮的状态。注意与剧级收藏区分：剧级收藏在 UserDefaults 的 DramaDetail.favorite.*
position_secondsREAL NOT NULL DEFAULT 0 上次播到的秒数（浮点，保留小数）。0 表示没播过或从头开始
position_totalREAL NOT NULL DEFAULT 0 该资源总时长（秒）。0 = 时长未知：此时不计算进度比例、不判「已看完」
updated_atTEXT可空 ISO8601，本行最近一次写入时间。做「最近观看」排序时用它（目前尚未用于排序） 
CREATE TABLE IF NOT EXISTS episode_actions (
    site TEXT NOT NULL,
    drama_id TEXT NOT NULL,
    episode_id INTEGER NOT NULL,
    liked INTEGER NOT NULL DEFAULT 0,
    saved INTEGER NOT NULL DEFAULT 0,
    position_seconds REAL NOT NULL DEFAULT 0,
    position_total REAL NOT NULL DEFAULT 0,
    updated_at TEXT,
    PRIMARY KEY (site, drama_id, episode_id)
);
派生口径（在 PlaybackProgress / Actions 里，不落库）： 进度比例 fraction = clamp(position_seconds / position_total, 0, 1)； 已看完 = position_total > 0 且 position_seconds ≥ position_total − 5。 续播条件 = 已播 > 3 秒、未看完、且 position_seconds < 当前总时长 − 5；不满足就从头播（时长变短 / 已到片尾都从头）。

05表 4 · local_actions（本地资源兜底表）

同一套行为字段，但主键换成资源文件的相对路径。 用于「拿不到服务端集 id」的资源：散装 HLS 条目、普通视频文件、以及从没进过剧集页缓存的历史条目。 与 episode_actions 互不覆盖：一条资源只会落在其中一张表里，读取侧按「先 id 后路径」兜底。

字段类型约束 / 默认含义与取值写入时机读取方
media_pathTEXT PK NOT NULL 资源文件相对下载根目录的路径，带前导斜杠：
剧内一集 /剧名/第01集/playlist.m3u8
散装 HLS /条目名/playlist.m3u8
普通文件 /xxx.mp4
由 EpisodeActionsStore.relativePath(for:) 统一生成（standardizedFileURL 归一化后去掉根目录前缀） 		与 episode_actions 完全相同的关键时机（同一个 PlaybackProgressTracker，只是 identity 不同） 已下载列表副行（allLocalActions() 一次读全表）

播放页续播（actions(for: .localPath)）
likedINTEGER NOT NULL DEFAULT 0 点赞（0/1）
savedINTEGER NOT NULL DEFAULT 0 收藏（0/1）
position_secondsREAL NOT NULL DEFAULT 0 上次播到的秒数
position_totalREAL NOT NULL DEFAULT 0 总时长（秒），0 = 未知
updated_atTEXT可空 ISO8601，最近写入时间同上同上 
CREATE TABLE IF NOT EXISTS local_actions (
    media_path TEXT NOT NULL PRIMARY KEY,
    liked INTEGER NOT NULL DEFAULT 0,
    saved INTEGER NOT NULL DEFAULT 0,
    position_seconds REAL NOT NULL DEFAULT 0,
    position_total REAL NOT NULL DEFAULT 0,
    updated_at TEXT
);
路径键的代价：文件被移动 / 重命名 / 重新下载到不同目录，这条记录就认不出来了（id 主表没有这个问题）。 另外删除资源时必须显式 removeActions，否则库里留下永远读不到的死行 —— 现在 delete(at:) / deleteSeries / deleteTasks(ids:) 三条删除路径都已接上清理。

06drama_cache.page_meta 的 JSON 内部字段

这一列是 TEXT，里面存 JSON。savePageMeta 采用合并式覆盖：读出旧 JSON、把本轮字段并进去、再整体写回， 所以历史字段不会被本轮没抓到的字段冲掉。字段来自两处：DOM 提取脚本 dramaMetaJS 的返回值，以及收割器补充的派生字段。

JSON 键类型来源含义
urlstringDOM：location.href提取时的页面地址
titlestringDOM：document.title页面标题（可能带营销后缀）
ogImagestringDOM：meta[property=og:image] → twitter:image封面候选；非空时同时写入 cover 列
ogTitlestringDOM：meta[property=og:title]OG 标题
keywordsstringDOM：meta[name=keywords]页面 keywords（调查用）
descstringDOM：meta[name=description] → og:description简介候选；非空时同时写入 intro 列
imgsstring[]DOM：前 40 个 img 的 currentSrc/src页面图片列表（调查用）
textstringDOM：body.innerText 压空白后前 500 字正文摘要（调查用）
coverstring收割器派生ogImage 非空时补写，与 cover 列同值
introstring收割器派生desc 非空时补写，与 intro 列同值
page_titlestring收割器派生title 非空时补写（保留原始标题，便于和清洗后的剧名对照）
tagsstring接口拦截（DramaSession 解密响应）标签数组 join(" ")，同时写入 tags 列
tags_sourcestring收割器写入目前只有 "api" 一种取值。nil（旧缓存）视为缺失，进页会自动补采一次
tags 的空值约定：抓不到标签时写 NULL、绝不写空串。空串会被 ViewModel 当成「已缓存」而永久跳过补采 （这是修过的一个真实 bug）；历史脏数据里的空串也一律归为「无」。

07键规则与身份解析

7.1 MediaIdentity：一条资源属于谁

enum MediaIdentity: Hashable {
    case episode(site: String, dramaID: String, episodeID: Int)   // → episode_actions
    case localPath(String)                                      // → local_actions
}

解析口径只有一处：EpisodeActionsStore.identity(...)，播放队列、下载列表、删除清理三方共用，避免「写到 A 读到 B」。

入口拿得到的身份解析路径落到哪张表
剧集页点已下载集 → 沉浸式播放 DramaTarget(site, dramaID) + ApiDramaEpisode.id ImmersivePlaybackRequest.target 直达 → DramaCache.seriesIdentity(site:dramaID:) 取「集号→集 id」映射 episode_actions（无歧义）
下载页 → 剧详情页点集播放 只有剧名 + 目录名「第NN集」 DramaCache.seriesIdentity(forSeriesName:) 按 name 反查（ORDER BY fetched_at DESC 取最近一条），再用 episodeSort(fromFolderName:) 解析集号 反查命中 → episode_actions；未命中 → local_actions
下载页主列表点条目（AVKit 播放） 剧名 + 目录名，或什么都没有（散装） 同上；seriesName == nil 时直接用资源路径 散装 / 普通文件 → local_actions
磁盘扫描收编的历史条目 只有文件路径 该剧若从没进过剧集页缓存，库里查不到 → 退回路径 local_actions

7.2 路径与集号的生成规则

规则实现说明
下载根目录DownloadEngine.downloadsDir Documents/Downloads；环境变量 SMARTDOWNLOADER_DIR 可重定向（冒烟隔离）
media_pathEpisodeActionsStore.relativePath(for:) 文件 URL 经 standardizedFileURL 归一化后，去掉根目录前缀，保留前导斜杠；不在根目录下则用绝对路径兜底
集号解析DownloadManager.episodeSort(fromFolderName:) 严格匹配「第<纯数字>集」：必须以「第」开头、含「集」、中间全是数字；否则返回 nil（不猜）
剧目录名DownloadEngine.seriesDirectory(for:) 剧名 sanitize 后的目录名；播放页扫盘定位剧集依赖它（改命名规则要同步评估 PlaybackQueueService）
HLS 播放地址 ≠ 键LocalMediaServer.playbackURL(forFolder:) 实际播放走回环 http://127.0.0.1:<port>/…，键一律用本地文件路径，否则端口一变进度就全丢

08建表与迁移历史

8.1 两套建表入口（同一个文件）

入口触发做什么版本管理

8.2 v0 → v1：把散在 UserDefaults 的行为数据搬进库

旧 UserDefaults 键旧值形态搬到规则
DramaPlayer.liked.<集目录相对路径>Bool episode_actions.liked 或 local_actions.liked 路径补上 /playlist.m3u8 得到资源路径；集目录必须还在磁盘上，否则跳过（不搬死数据）；能按剧名+集号反查到 id 就进主表，否则进兜底表
DramaPlayer.saved.<集目录相对路径>Bool …saved同上
PlaybackProgress.<资源相对路径>String "秒|总秒" position_seconds / position_total 上一版（未发布）的进度写法，同样按身份判定落主表或兜底表
搬完即删源键，只删这三类前缀；DramaPlayer.muted / cleanScreen / showRemainingTime 等全局开关原样保留（它们不属于某一集）。冲突合并用 liked = MAX(liked, excluded.liked)， 已点赞不会被一次迁移抹掉；位置字段直接覆盖。

8.3 以后加字段怎么做

// 例：给每集加「观看次数」
private static let schemaVersion = 2        // 1 → 2
if version < 2 {
    sqlite3_exec(db, "ALTER TABLE episode_actions ADD COLUMN watch_count INTEGER NOT NULL DEFAULT 0;", ...)
    sqlite3_exec(db, "ALTER TABLE local_actions   ADD COLUMN watch_count INTEGER NOT NULL DEFAULT 0;", ...)
    // 需要回填历史数据就在这里做

sqlite3_exec(db, "PRAGMA user_version = 2;", ...)

09不在库里的存储（对照清单）

判断标准：需要按剧/集建关系、以后要加字段的 → 进 SQLite； 全局开关、一次性配置、凭据、上次访问页 → UserDefaults；媒体与调查产物 → 磁盘。

10典型查询（表已经支持的关系能力）

下面每条都能直接在 drama_cache.sqlite3 上跑（把库拷到 Mac 后用 sqlite3 打开即可）。

10.1 某剧逐集状态：下载 + 点赞 + 收藏 + 播到哪

SELECT e.sort, e.episode_id, e.downloaded, e.folder,
       COALESCE(a.liked, 0) AS liked,
       COALESCE(a.saved, 0) AS saved,
       a.position_seconds, a.position_total
FROM drama_episodes e
LEFT JOIN episode_actions a
       ON a.site = e.site AND a.drama_id = e.drama_id AND a.episode_id = e.episode_id
WHERE e.site = ? AND e.drama_id = ?
ORDER BY e.sort;

10.2 这部剧看到第几集（按最近写入时间）

SELECT e.sort, a.position_seconds, a.position_total, a.updated_at
FROM episode_actions a
JOIN drama_episodes e ON e.site = a.site AND e.drama_id = a.drama_id AND e.episode_id = a.episode_id
JOIN drama_cache  c ON c.site = e.site AND c.drama_id = e.drama_id
WHERE c.name = ?
ORDER BY a.updated_at DESC
LIMIT 1;

10.3 收藏过的集（跨剧清单）

SELECT c.name, e.sort, a.updated_at
FROM episode_actions a
JOIN drama_episodes e ON e.site = a.site AND e.drama_id = a.drama_id AND e.episode_id = a.episode_id
JOIN drama_cache  c ON c.site = e.site AND c.drama_id = e.drama_id
WHERE a.saved = 1
ORDER BY c.name, e.sort;

10.4 已下载但没看完的集（续播候选）

SELECT c.name, e.sort, a.position_seconds, a.position_total
FROM episode_actions a
JOIN drama_episodes e ON e.site = a.site AND e.drama_id = a.drama_id AND e.episode_id = a.episode_id
JOIN drama_cache  c ON c.site = e.site AND c.drama_id = e.drama_id
WHERE e.downloaded = 1
  AND a.position_total > 0
  AND a.position_seconds < a.position_total - 5
ORDER BY a.updated_at DESC;

10.5 本地兜底表里播到一半的资源

SELECT media_path, position_seconds, position_total
FROM local_actions
WHERE position_total > 0 AND position_seconds < position_total - 5;

11已知取舍与风险

#事项影响现状 / 可选改法
1按剧名反查身份有歧义 两部剧同名（或同剧多站点）时，下载页入口与剧集页入口可能落到不同记录 已打 AMBIGUOUS 日志、取 fetched_at 最近一条。彻底解法：下载时把 (site, drama_id) 落到条目上（drama_episodes 已有 folder 可对应），不再靠名字猜
2播放中只攒内存 进程被硬杀时，最多丢最后一段没 flush 的位置 已覆盖暂停 / seek 收尾 / 切集 / 退出 / 进后台五个时机；要更稳可加定时 flush（代价是写库频率）
3saveInfo 先删后插 刷新集列表会把 downloaded/folder 清成 0/NULL（与注释宣称的「保留」不符） 靠 reconcileDownloaded 磁盘对账恢复；行为数据表不受影响。要修就把 DELETE 改成按 id upsert + 删除已消失的集
4无外键、无级联 直接改库不会联动；一致性完全靠代码 删除资源的三条路径已显式清行为数据。若要强约束可加 FOREIGN KEY + PRAGMA foreign_keys=ON（需评估旧库兼容）
5无额外索引 WHERE name=? 反查是全表扫 剧数量级小，暂不加；量大时 CREATE INDEX idx_drama_name ON drama_cache(name)
6无显式事务、未开 WAL reconcileDownloaded 逐集 UPDATE = N 次 autocommit，集数多时偏慢 可把批量写包进 BEGIN/COMMIT；读多写少场景可评估 WAL
7路径键脆弱 local_actions 的记录在文件改名 / 移动 / 换目录重下后认不出来 这是「没有服务端 id」的必然代价；能进剧集页缓存的集会自动升级到 id 主表
8主线程 IO 所有读写在主线程（与 DramaCache 同约定） 列表侧已收敛为「按剧一次读全 + 本地表一次读全」，不再逐行开库
9position_total = 0 表示时长未知 此时不显示进度比例、不判「已看完」 刻意设计：避免把「未知」当成 0% 或 100%
10剧级聚合未落列 「看到第几集」目前只能实时 JOIN 算 表已支持（见 10.2）；要做剧行展示或最近观看列表时再决定要不要冗余列
